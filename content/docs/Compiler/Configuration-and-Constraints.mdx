Hardware parameters and config schema consistency constrain compiler behavior. This section covers the expected formats and validation rules.

## Hardware Parameters

The compiler accepts the following hardware parameters.

| Parameter | Meaning | Typical Values |
| --- | --- | --- |
| `T` | Macro group size | `1`, `4`, `8`, `12`, `16` |
| `K` | Macro group count | `1`, `4`, `8`, `12`, `16`, `32`, ... |
| `B` | NoC flit size / bandwidth unit | `8`, `16` |
| `C` | Core count | Positive perfect square (`1`, `4`, `9`, `16`, `64`, ...) |
| `batch-size` | Compilation batch scheduling granularity | Positive integer |

C must be a perfect square because the compiler maps cores to a P×Q grid. T and K determine the CIM array parallelism within each core.

## Config Format Compatibility

Compiler accepts two config families.

<Accordions>
<Accordion title="Simulator-Native Config (Preferred)">

```json
{
  "chip_config": {
    "core_config": {
      "cim_unit_config": {
        "macro_group_size": 8
      }
    },
    "network_config": {
      "bus_width_byte": 16
    }
  }
}
```

Validation checks both `T` and `B` against this format.

</Accordion>
<Accordion title="Legacy Compiler Config (Supported)">

```json
{
  "macro": {
    "n_group": 16,
    "n_macro": 128,
    "n_row": 16,
    "n_comp": 32,
    "n_bcol": 64
  },
  "memory_list": [
    {
      "identifier": "global",
      "addressing": {"offset_byte": 0, "size_byte": 1048576}
    }
  ]
}
```

`T` is derived as `n_macro / n_group`. `B` is not validated in this legacy format.

</Accordion>
</Accordions>

## T/B Consistency Rule

When running `cim-compiler network` (full pipeline), CG parameters and hardware config must agree — a mismatch causes compile-time failure before OP-level generation. In staged compilation (`cg-level` then `op-level`), ensure both steps use consistent hardware parameters and a matching config file to avoid address layout mismatches downstream.

## Troubleshooting

<Accordions>
<Accordion title="Model or Config File Not Found">

Symptoms: immediate path resolution errors on `model-path` or `config-path`.

Fix: Use absolute paths, or verify the current directory before running the compiler.

</Accordion>
<Accordion title="Invalid Parameter Value">

Symptoms: errors such as `Invalid T value` / `Invalid B value`.

Fix: Use supported domains (`T in {1,4,8,12,16}`, `B in {8,16}`).

</Accordion>
<Accordion title="T/B Mismatch with Config">

Symptoms: validation message shows conflicting values between CLI args and config file.

Fix: Either rerun CG/network with matching params, or choose a config file with matching hardware fields.

</Accordion>
<Accordion title="OP-Level Synchronization Validation Failure">

Symptoms: `expected_writes` mismatch or `WAIT` without producer writes.

Fix: Inspect CG instruction `write_id` / `wait_write` generation and ensure stage dependency metadata remains intact.

</Accordion>
</Accordions>

<Callout type="warn" title="Keep Parameters Aligned Across Stages">
If you run staged compilation (`cg-level` then `op-level`), use consistent hardware parameters and matching config in both steps.
</Callout>
